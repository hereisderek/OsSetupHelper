## Critical (found mid-refactor, not originally on this list)

- [x] **No role was ever actually being installed.** `orchestrator.py` passed the discovered-role lists to Ansible as `-e discovered_apps_common='["chrome","vscode"]'` — one `-e key=value` per key. Verified against ansible-core 2.15.13 (the version `requirements.txt` pins): `-e key=value` never parses the value as JSON/YAML, so the list arrived in `bootstrap.yml` as a raw string, and looping over a string in Jinja iterates its characters. Net effect: `active_apps_common` (etc.) always computed empty, so no selected role ever ran, regardless of `config.yaml`. **Fixed** by folding the discovered-roles dict into the same `vars_file` that's already passed via `-e @file` (which does parse correctly) — see `orchestrator.py:main()` and `write_temp_vars_file`. Verified end-to-end in an isolated Ansible harness (fake roles actually execute now).
- [x] A second, compounding bug in the same code path: the `active_settings_common`-style `set_fact` Jinja templates rendered to a **string**, not a native list, even when fed a real list — un-trimmed `{% for %}/{% if %}` whitespace defeats Ansible's string→list auto-cast. Fixed by using `{%- -%}` trim-block syntax in the new `active_roles` block in `bootstrap.yml`.
